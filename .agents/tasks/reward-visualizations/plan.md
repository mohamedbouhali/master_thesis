- The canonical input is `reward_scores/gemma-4-31B-it/all_results.json`, whose top-level object has `summary` and `results`. It contains 142/142 completed records and no score failures. Each result has `status`, `dataset_index`, string `session_id`, `prompt`, scalar `reward`, `components`, `metrics`, `elapsed_seconds`, and judge metadata.
- All 142 current rows have numeric values for eight component scores (`token_efficiency`, `tool_efficiency`, `reasoning_efficiency`, `context_efficiency`, `redundancy_penalty`, `output_density`, `duration_efficiency`, `llm_judge`) and ten raw metrics (`input_tokens`, `output_tokens`, `total_tokens`, `num_tool_calls`, `assistant_turns`, `reasoning_chars`, `tool_output_chars`, `code_written_chars`, `redundancy_ratio`, `duration_ms`). The implementation will still discover numeric fields dynamically and filter missing, boolean, null, non-finite, and non-numeric values so future partial files remain usable.
- `reward_scores/gemma-4-31B-it/input.json` contains the ground-truth `agentbench.result` boolean, plus `agentbench.task/index/tool_calls/turns`. Its 142 unique `session_id` values join completely to the score results: 73 passed and 69 failed. The CLI will automatically look for sibling `input.json`, join labels by `session_id` (with `dataset_index` only as a guarded fallback), and omit stratified output with a clear console notice if labels are unavailable or ambiguous.
- Real-data characteristics relevant to honest plotting: reward ranges 0.3404–0.7347 (mean 0.5985, median 0.6349); passed reward mean/median are 0.6416/0.6653 and failed reward mean/median are 0.5530/0.5251. `reasoning_efficiency`, `reasoning_chars`, and `code_written_chars` are constant, while `duration_efficiency` reaches -0.0151 despite signal documentation claiming [0,1]. Plots must use observed ranges rather than force [0,1], retain constant fields in the component summary with a constant-data annotation, and exclude constant fields from correlation/scatter panels where correlation is undefined.
- There is no repository plotting/script convention, test suite, `pyproject.toml`, or `Makefile`; the requested root-level `plot_reward_distributions.py` is therefore the clearest source location. Generated files will go to `reward_scores/gemma-4-31B-it/plots/` by default, keeping analysis beside its source data without altering reward JSON.
- Use Matplotlib directly plus NumPy rather than adding pandas/seaborn. The current Python environment has NumPy 1.24.0 but no Matplotlib/Pillow/pandas/seaborn, while `requirements.txt` declares `numpy~=1.23.5`; add one exact Matplotlib pin compatible with Python 3.9 and NumPy 1.23.5 only because rendering is required. Do not add or install seaborn/pandas/Pillow; Matplotlib can both render and decode its generated PNGs during verification.
- Use a fixed Matplotlib style/config, accessible colorblind-safe palette, deterministic ordering, fixed output names, high DPI, constrained layouts, readable labels/units, legends, grids, and per-panel sample counts. Histogram density overlays will only be drawn when there are enough non-constant samples; otherwise show the histogram/marker and explain why density was omitted. (The “KDE” requirement can be satisfied without seaborn by a deterministic NumPy Gaussian-kernel density estimate with a documented bandwidth guard.)
- The plot set will be: `reward_distribution.png` (histogram plus guarded KDE, mean and median markers, n); `component_distributions.png` (small-multiple distributions for every discovered component, including constant-field annotation); `metric_correlation_heatmap.png` (Pearson correlations among reward and informative non-constant component/raw metric fields, pairwise finite observations and annotated coefficients); `reward_vs_key_metrics.png` (reward against total tokens, tool calls, duration, and LLM judge when available, with pass/fail color and deterministic trend line only where valid); `component_summary.png` (compact horizontal mean with standard-deviation spread plus median markers); and `reward_by_agentbench_result.png` (passed-vs-failed box/violin or jittered box comparison, only when the sibling label join is valid). Raw skewed resource metrics should use sensible transformed/log axes where values are positive, while captions/labels retain original units.
